## 我的打法与学到的内容

前中期我主要使用 `雷击` 控制对方前排，同时靠无属性伙伴补充资源与阻挡。中期用 `掌门 穆伶` 的绝技把双方等费用伙伴退回手牌，证明绝技选择、费用差和双方目标链路可以直接由 agent 操作。

主要失误：

1. 我曾在对方回合用英雄透支支付 `雷击` 防御。由于卡牌在自己回合结束时重置，而不是下个自己回合开始时重置，这导致英雄在接下来的自己回合仍横置，整回合失去 4 气资源。除非能阻止致命效果，否则不应轻易用英雄透支。
2. 前期过度把资源用于逐次施放 `雷击`，场面发展速度落后。`雷击` 的威力 3 是防御门槛，命中只造成 1 点伤害，不能把“威”当作伤害。
3. 后期我先后测试了“双低生命阻挡者”和“单个 4 生命阻挡者”。后者能承受 `雷击/奥术箭矢 + 两次 1 点普攻`，但被点燃后会在结算时死亡。持续伤害必须进入下一回合生存估算。
4. `屠魔者杀手` 的速攻适合立刻换掉对方攻击单位。第 19 回合我用残血 `屠魔者武士` 主动击杀对方杀手，确实减少了一路攻击，但之前积累的生命差和场面差已经无法逆转。

## 明确发现的实现 Bug

### [高置信] `回收小精灵` 将死亡牌放回牌库时没有重置运行时状态

卡牌文本是：“入场：将你弃牌堆的 1 张牌放到卡组顶。”按卡牌语义，一张牌从弃牌堆回到牌库、再抽入手牌后，应恢复为可正常使用的新区域状态；至少伙伴的 `current_life` 应回到印刷生命，旧战场坐标和致死来源不应继续存在。

本局对同一个实例 `ci_21`（`屠魔者杀手`，印刷生命 `life: 1`）形成了完整证据链：

1. `2026-07-19T04:57:35.914654Z`：`ci_21` 被摧毁。随后状态显示它在弃牌堆，`current_life: 0`、旧 `position: {col:0,row:0}`、`statuses.lethal_source_player: 2`。
2. `2026-07-19T05:05:16.701543Z`：我在 `回收小精灵` 的 `graveyard_to_deck_top` 选择中提交 `{"selected":["ci_21"]}`。
3. `2026-07-19T05:07:57.053793Z`：下一次 `draw_card` 事件把 `ci_21` 抽回手牌，但它仍为 `current_life: 0`，并保留旧坐标 `{col:0,row:0}` 和 `lethal_source_player: 2`。
4. `2026-07-19T05:08:52.709343Z`：我提交召唤 `ci_21`，支付 3 气。服务端接受。
5. `2026-07-19T05:08:52.717388Z`：`summon` 事件明确显示该伙伴以 `current_life: 0` 进入战场，旧致死状态仍在；随后的 `state_sync` 也将它保留在单位区，没有立即清理。
6. `2026-07-19T05:10:32.494279Z`：它又受到 1 点伤害后变成 `current_life: -1`，才再次进入弃牌堆。

这不是 agent 对文本的主观误解：服务端同时给出了印刷 `life: 1` 和运行时 `current_life: 0`，并允许 0 生命伙伴完成召唤。房间日志的后续快照也保留了该实例的负生命和旧坐标。

建议修复方向：卡牌从弃牌堆移动到牌库时清除区域相关运行时状态（坐标、横竖、致死来源、临时状态等），并在伙伴进入牌库或手牌时将 `current_life` 恢复为基础生命。作为第二层保护，召唤处理不应允许 `current_life <= 0` 的伙伴留在战场。

建议回归测试：

1. 伙伴死亡进入弃牌堆。
2. 用 `回收小精灵` 放到牌库顶。
3. 抽牌后断言生命恢复、坐标为空、致死/临时状态已清除。
4. 召唤后断言它以基础生命正常入场。

## 协议与 agent 工具评价

当前框架已经足够支持“两个 Codex agent 直接玩完整一局，并在真实游戏过程中发现效果异常”。这局不仅正常到达 `game_over`，还通过阅读卡牌文本与观察事件状态发现了一个真实、可复现的区域迁移 Bug。

比较影响效率的不是动作 JSON，而是观察输出：

- 每次 `state_sync` 都非常大，经常达到数万字符，终端输出被截断。agent 必须反复用 `jq` 从 transcript 提取手牌、单位、阶段和待处理动作。
- `defense_window` 虽然存在于完整状态中，但没有一个足够醒目的简短“现在需要你响应”通知。两次对方都需要额外提醒我处理防御窗口，导致不必要等待。
- 建议为 agent-player 增加可选的 compact observation 模式，只输出：阶段、当前玩家、回合、双方公开场面、自己的手牌/资源、合法动作或待响应摘要；完整 `state_sync` 仍写 transcript。
- 建议收到需要本玩家响应的 `defense_window`、`waiting_action` 时，额外输出一行紧凑提示，包含超时、攻击牌、目标、候选和示例动作。

动作协议本身覆盖面足够。本局实际走通了普通动作、带 payment 的召唤、法术目标、组合防御、待处理选择和绝技选择，没有出现“后端能力存在但 agent 完全无法触发”的阻断。

## 结论

这次实战验证了用户设想的最小闭环：

1. 两个 Codex agent 可以只通过后端完成一局真实对战。
2. agent 能从卡牌文本形成预期。
3. agent 能将预期与事件/状态结果比较。
4. 当结果明显不合理时，能用 transcript 形成可复现证据。
5. 复盘可以落到文档，供后续 agent 继续学习。

下一轮最值得做的是修复 `回收小精灵` 暴露的区域迁移状态重置问题，并给 agent-player 增加紧凑观察输出；不需要引入传统 RL 或复杂的自动文本裁判。
